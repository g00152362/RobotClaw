# RobotClaw V1.0 平台需求列表

> 基于 RobotClaw-V1.0-宣传稿.md 提取，参考 RoboHarness Design Doc 技术细节补充
> 日期：2026-06-20

---

## 需求编号规则

- **U**: 理解层 (Understand)
- **E**: 执行层 (Execute)
- **V**: 进化层 (eVolve)
- **P**: 平台基础设施 (Platform)
- **S**: 场景模板 (Scene)
- **G**: 工程生态层 (enGineering ecosystem)

优先级：P0=MVP必须 / P1=引擎完善阶段 / P2=真机验证阶段 / P3=产品化阶段

---

## 一、理解层 (Understand)

### U1. SOP Compiler — SOP智能编译器

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| U1.1 | 步骤提取 | AI将自然语言SOP拆分为结构化步骤列表，每步包含：动作、目标、条件、参数 | P0 |
| U1.2 | 意图映射 | 将每步动作映射到Skill Registry中对应的Skill，使用LLM + Skill能力声明匹配 | P0 |
| U1.3 | DAG构建 | 基于步骤间的数据依赖和控制依赖构建有向无环图（DAG），Phase 1支持顺序+条件分支，Phase 2增加并行和循环 | P0(顺序+分支) / P1(并行+循环) |
| U1.4 | 静态校验 | 自动检查：Skill存在性、输入/输出类型匹配、前置条件可满足性、DAG合法性（无环路） | P0 |
| U1.5 | 人工审核UI | 可视化展示SOP原文与DAG映射对照，高亮低置信度映射，支持一键确认或手动微调 | P0 |
| U1.6 | 编译准确率 | 标准工业SOP ≥ 80%自动正确映射（步骤级准确率），低于60%回退到"LLM辅助+人工确认"模式 | P0 |
| U1.7 | 编译缓存 | 编译结果缓存（Task Memory），key为SOP文本+Skill Registry版本的hash，命中时0ms返回 | P0 |
| U1.8 | 黄金集基线 | 建立标注黄金集（10+标准巡检SOP，人工标注期望DAG），用于编译准确率持续衡量 | P0 |
| U1.9 | LLM Prompt策略 | 结构化输出约束（固定JSON schema）、Few-shot examples（3-5个）、Chain-of-thought（条件分支场景）、幻觉防护（静态校验+embedding相似度阈值） | P0 |

### U2. Skill生态 — 技能标准化与注册

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| U2.1 | Skill接口标准 | 每个Skill必须定义：输入类型（typed schema）、输出类型、前置条件（声明式谓词）、后置条件、失败模式枚举、恢复策略 | P0 |
| U2.2 | Skill Registry | 技能注册中心，支持注册/发现/查询，Phase 1内部使用 | P0 |
| U2.3 | Skill版本管理 | 支持Skill多版本共存、版本依赖解析、能力声明校验 | P1 |
| U2.4 | 前置/后置条件 | 使用与语言无关的条件DSL：属性访问、比较运算、布尔运算、内建函数（distance_to, contains, len）。机器人端由C++求值引擎解析（Phase 1: JSON规则引擎, Phase 2+: 可选Lua嵌入） | P0 |
| U2.5 | 恢复策略枚举 | 支持参数化恢复策略：retry_after(delay, max)、invoke_skill(skill_name, params)、escalate_to_human(context)、skip_and_log(reason)、abort_dag(reason) | P0 |
| U2.6 | 巡检核心Skill桩 | Phase 1实现5-6个核心Skill桩：导航(navigate_to_waypoint)、热成像(capture_thermal_image)、异常检测(detect_anomaly)、告警(alert_operator)、回基站(return_to_base)、日志记录(log_result) | P0 |
| U2.7 | Skill跨本体迁移 | 同一Skill意图根据不同机器人本体的e-URDF描述，自动进行约束适配和验证（Teach Once, Embody Anywhere） | P2 |
| U2.8 | Skill能力声明 | 每个Skill声明其能力标签、适用本体列表、所需传感器、环境要求，供SOP Compiler匹配和Skill Registry查询 | P0 |

### U3. e-URDF — 扩展机器人描述

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| U3.1 | e-URDF标准定义 | 在传统URDF基础上扩展：关节力矩限制和软限制、工具坐标系、工作空间边界、可执行Skill清单、适用仿真资产、Benchmark | P0 |
| U3.2 | e-URDF解析器 | 解析e-URDF文件，构建机器人物理模型供执行引擎和Skill迁移使用 | P0 |
| U3.3 | 身体约束校验 | 执行前基于e-URDF校验Skill参数是否在机器人物理能力范围内（关节范围、力矩限制、工作空间） | P1 |

### U4. Provider — 边云协同多模型推理

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| U4.1 | Provider抽象接口 | 统一封装异构模型为标准能力接口（远端Python + 边缘C++），支持声明、路由、降级、审计 | P0(接口定义) / P1(完整实现) |
| U4.2 | 首个远端Provider | Phase 1硬编码单一LLM Provider（GPT-4o或通义千问），用于SOP编译 | P0 |
| U4.3 | 边缘推理运行时 | 机器人端C++推理基础设施：模型加载/卸载/热切换、推理调度、GPU/NPU资源管理，支持ONNX Runtime / TensorRT / OpenVINO / RKNN | P0(基础框架) / P1(多硬件适配) |
| U4.4 | 首批边缘模型 | Phase 1部署核心边缘模型：目标检测（YOLO/RT-DETR）、异常识别（分类模型）、语音ASR（Whisper small）、语音TTS | P0(检测+ASR) / P1(异常+TTS+VLM) |
| U4.5 | 边云路由策略 | 边缘优先：延迟敏感任务（<100ms）强制走边缘，边缘不可用时回退远端；离线场景全部走边缘 | P0(基础路由) / P1(智能路由) |
| U4.6 | 多远端Provider适配 | 支持云端API（GPT-4o、通义千问）和本地私有化大模型，支持VLM、VLA、VLN、世界模型 | P1 |
| U4.7 | Provider降级策略 | 远端不可用→降级到边缘小模型或规则引擎；边缘GPU过载→降低推理精度或排队等待 | P1 |
| U4.8 | 边缘模型版本管理 | 远端管理模型版本，定期向边缘分发新版本模型（增量下载、沙箱验证、自动回滚） | P1 |
| U4.9 | 模型输出审计 | 记录每次模型调用（远端+边缘）的输入摘要、输出摘要、耗时、硬件使用、成本，统一格式支持回溯 | P1 |
| U4.10 | Skill推理需求声明 | Skill接口中声明所需推理能力（类型、延迟约束、优先部署位置、回退策略），供Provider Router匹配 | P1 |

## 二、执行层 (Execute)

### E1. 执行引擎 — DAG遍历与状态机

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| E1.1 | DAG遍历器 | 按DAG拓扑序执行Skill节点，Phase 1支持顺序+条件分支，Phase 2支持并行fork/join和循环 | P0(顺序+分支) / P1(并行+循环) |
| E1.2 | 执行状态机 | 每个Skill执行的完整生命周期管理：pending → running → success/failed/timeout → recovery → ... | P0 |
| E1.3 | 运行时环境感知 | 执行过程中实时获取传感器数据，理解当前环境与预期的差异 | P1 |
| E1.4 | 动态执行调整 | 根据运行时环境数据调整执行策略（路径、参数、速度等），不是死板执行预设计划 | P1 |
| E1.5 | 异常检测与恢复 | 检测到异常时，自主选择恢复策略（重试、换路、跳过、请求人工），基于Skill定义的失败模式和恢复策略 | P0 |
| E1.6 | 级联熔断 | 连续3个Skill失败自动暂停任务，支持断点恢复（从失败点继续执行） | P1 |
| E1.7 | 95%+自主率 | 自主率 = 无需人工介入完成的Skill执行次数 / 总Skill执行次数，目标≥95%，以连续20+次任务运行的均值衡量 | P2(衡量) / P3(达标) |
| E1.8 | 完整诊断上下文 | 失败时提供：传感器快照、机器人位姿、错误链、前序Skill输出、环境状态，供人工判断 | P1 |
| E1.9 | 状态追踪 | 完整记录执行过程中每一步决策和状态变化，支持回溯分析 | P0 |

### E2. 人工升级与接管

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| E2.1 | 人工升级路径 | 当自主恢复失败时，系统自动通知人类操作员，提供诊断上下文和推荐操作建议 | P1 |
| E2.2 | 一键接管 | 操作员可通过Dashboard一键接管机器人控制，手动完成当前Skill后归还控制权 | P1 |
| E2.3 | 实时告警 | Dashboard实时展示失败告警、风险等级变化、需要人工介入的节点 | P1 |

### E3. Dashboard — 执行过程驾驶舱

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| E3.1 | 实时任务状态 | 展示当前任务的DAG执行进度、每个Skill节点的状态（待执行/执行中/完成/失败） | P1 |
| E3.2 | 机器人本体状态 | 实时展示机器人位姿、关节状态、传感器数据、电池电量等 | P1 |
| E3.3 | Skill调用可视化 | 展示当前正在执行的Skill、输入参数、输出结果、执行耗时 | P1 |
| E3.4 | 执行决策可视化 | 展示执行引擎的运行时判断和调整决策（为什么选择这条路径、为什么调整参数） | P2 |
| E3.5 | 人工接管入口 | 在Dashboard中提供接管按钮，支持紧急停止、手动控制、断点恢复操作 | P1 |
| E3.6 | Practice回放 | 回放历史任务执行的完整记录（传感器数据流、决策过程、Skill调用链） | P2 |
| E3.7 | Memory命中展示 | 展示当前执行中命中了哪些记忆原子（任务记忆、执行记忆、空间记忆）及其对执行的影响 | P2 |

## 三、进化层 (Evolve)

### V1. Practice — 执行实践记录

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| V1.1 | 执行数据采集 | 每次任务执行完整记录：传感器数据流、决策过程、Skill调用链、环境状态变化，按统一时间线对齐 | P0 |
| V1.2 | Practice存储 | 将采集数据持久化为结构化的Practice记录，支持查询和回放 | P0 |
| V1.3 | 自动分析 | 对每条Practice自动分析，提取结构化记忆原子（Memory Atom）：成功模式、失败教训、环境特征、最优参数 | P1 |
| V1.4 | 逐帧回放 | 支持按时间线逐帧回放Practice记录，用于事故分析和经验提炼 | P2 |

### V2. Memory — 三层记忆系统

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| V2.1 | 任务记忆 (Task Memory) | 缓存SOP到Skill DAG的编译结果，key=hash(SOP文本+Skill Registry版本)，命中时跳过LLM调用 | P0 |
| V2.2 | 执行记忆 (Execution Memory) | 记录Skill在特定环境+机器人型号下的历史执行数据（参数、耗时、成功率），自动推导推荐参数 | P0(基础记录) / P1(参数推导) |
| V2.3 | 空间记忆 (Spatial Memory) | 持久化机器人对环境的认知：设备位置、环境基线、最优路径、历史异常区域 | P1(仿真) / P2(真机) |
| V2.4 | 视觉参考 (Visual Reference) | Spatial Memory中每个landmark可携带视觉参考图片（正常/异常状态），支持自动采集、人工上传、异常存档，用于图像对比式异常检测 | P1(数据结构) / P2(自动采集+对比检测) |
| V2.5 | 记忆原子更新 | 新的Practice不断注入时，旧的记忆原子持续更新权重，记忆保持"活性" | P1 |
| V2.6 | 记忆管理Dashboard | 可视化查看/编辑三种记忆，支持手动失效和校准 | P3 |

### V3. Know/How — 知识与经验引擎

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| V3.1 | Know（离线知识炼化） | 将论文、代码、项目文档、失败报告、Benchmark结果编译成可检索、可复用的工程知识 | P2 |
| V3.2 | How（在线经验注入） | 执行卡住或风险升高时，实时给出最小、精准、带证据的提示（降低步长、检查限位、回退技能等） | P2 |
| V3.3 | 知识索引 | 支持对工程知识的结构化索引和语义检索，供SOP Compiler和执行引擎查询 | P2 |

### V4. Auto/Darwin — 自进化引擎

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| V4.1 | 候选Skill生成 | 基于积累的Practice数据，自动生成候选Skill的改进版本 | P3 |
| V4.2 | 六道关卡评测 | 候选Skill必须通过：多任务验证、扰动测试、多初始状态、回归测试、安全验证、性能基准 | P3 |
| V4.3 | Champion晋升 | 全部通过评测的候选Skill替代现有版本成为Champion Skill | P3 |
| V4.4 | 评测数据集 | 维护评测用的多场景数据集、扰动参数集、回归测试基线 | P3 |

### V5. 数据飞轮

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| V5.1 | 实时数据采集管线 | 执行数据实时采集并写入Practice | P0 |
| V5.2 | 实时记忆更新管线 | Practice数据触发记忆原子的实时更新 | P1 |
| V5.3 | 离线分析管线 | 定期离线分析：Skill参数调优、异常模式挖掘、巡检路径优化 | P2 |
| V5.4 | 跨项目知识沉淀 | 脱敏统计数据汇聚、Skill质量评分、通用推荐参数（跨不同客户项目） | P3 |
| V5.5 | 飞轮效果可衡量 | 可量化展示数据飞轮效果：SOP编译耗时趋势、导航效率趋势、异常检测精度趋势、执行正确率趋势、任务总耗时趋势 | P2 |

## 四、场景应用模板 (Scene Templates)

### S1. 模板系统

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| S1.1 | 模板定义标准 | 每个场景模板包含：预配置的SOP执行计划 + 已验证的Skill组合 + 环境参数模板 + 典型失败处理方案 | P0 |
| S1.2 | 模板角色定位 | 模板是面向集成商的交付单元：降低接入门槛（无需理解DAG/Skill概念）、固化行业Know-How、加速项目交付、提供质量基线 | P0 |
| S1.3 | 模板与Skill关系 | 模板是Skill的"上层编排"加行业参数化配置，同一组Skill可组成不同模板；模板包含已验证的SOP→Skill映射、推荐参数和失败处理方案 | P0 |
| S1.4 | 模板配置界面 | 集成商可通过界面配置模板参数（巡检路线、设备参数、告警阈值等），无需写代码 | P1 |
| S1.5 | 模板参数校验 | 配置参数时自动校验合法性（是否在机器人能力范围内、Skill是否支持等） | P1 |
| S1.6 | 模板版本管理 | 模板支持版本化，支持升级和回滚 | P2 |

### S2. 首批场景模板

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|

| S2.2 | 仓储物流模板 | 货架盘点 + 货物搬运 + 路径规划 + 库存核对 + 异常预警 | P3 |
| S2.3 | 矿山开采模板 | 矿道巡检 + 气体检测 + 结构安全评估 + 紧急撤离路径 | P3 |
| S2.4 | 管廊巡检模板 | 管道泄漏检测 + 温湿度监测 + 设备状态识别 + 定期报告 | P3 |

## 五、工程生态层 (Engineering Ecosystem)

### G1. Swarm — 多智能体协作

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| G1.1 | 角色分配 | 根据任务需求和机器人能力，自动分配协作角色（侦察、执行、确认等） | P3 |
| G1.2 | 任务分解 | 将复杂任务分解为多机器人可并行执行的子任务 | P3 |
| G1.3 | 状态共享 | 多机器人间实时共享任务状态、环境感知、异常信息 | P3 |
| G1.4 | 空间避让 | 多机器人在同一空间中运行时的路径协调和避让 | P3 |
| G1.5 | 人机协作 | 支持人类专家在高风险节点介入协作流程 | P3 |

### G2. Forge — 机器人接入

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| G2.1 | 资产编译 | 从机器人SDK、ROS2接口、文档和e-URDF出发，自动生成Skill清单、Provider清单、测试用例 | P2 |
| G2.2 | 首批机器人支持 | 支持宇树Go2/G1四足机器人、UR系列机械臂，通过RML（Robot Messaging Layer）接入，Phase 1使用ROS2 Adapter | P2 |
| G2.3 | RML通信抽象 | Robot Messaging Layer（pub/sub/service/param/action原语），Phase 1 ROS2 Adapter，Phase 2+ DDS/自定义协议 Adapter | P0(接口+ROS2 Adapter) / P2(DDS Adapter) |
| G2.4 | 接入模板 | 提供机器人接入的标准流程模板和文档，降低新机器人接入的工程量 | P2 |
| G2.5 | e-URDF定义工具 | 向导式e-URDF创建工具：URDF导入自动转换、向导表单逐步填写、模板继承快速派生、版本管理与回滚 | P1(导入+向导) / P2(模板继承+版本对比) |

### G3. ClawHub — 技能生态市场

| 编号 | 需求 | 描述 | 优先级 |
|------|------|------|--------|
| G3.1 | Skill上传/下载 | 集成商/开发者可上传和下载Skill | P3 |

## MVP (P0) 核心交付物

1. **SOP Compiler** — 五步编译流水线，≥80%准确率，编译缓存
2. **e-URDF标准** — 扩展机器人描述定义和解析器
3. **Skill接口标准** — 含5-6个巡检核心Skill桩
4. **DAG Schema** — 序列化格式 + 顺序/条件分支节点
5. **执行引擎骨架** — C++实现，状态机框架 + 基础顺序执行 + 异常恢复
6. **边缘推理运行时** — C++推理基础设施 + 首批边缘模型（目标检测+语音ASR）
7. **Practice记录基础** — 执行数据采集和存储
8. **Task Memory** — SOP编译结果缓存
9. **首个场景模板** — 电力巡检模板
10. **Docker容器化部署**（远端）+ C++原生部署（机器人端）
