**理解人类标准操作，越用越正确地执行**

## 一个被忽略的关键问题

你是机器人集成商。你的团队接到一个电力巡检项目，客户给了一份Word版的巡检SOP——200多条巡检规则，覆盖60个巡检点位。

接下来发生什么？

你的工程师一条一条把SOP翻译成ROS2代码。导航逻辑写一版，视觉检测写一版，异常处理写一版，告警上报写一版。调通了吗？到现场调试。环境跟仿真不一样，参数全部重调。好不容易上线了，客户说：第37条规则改了，巡检路线也调了。

代码返工。又是两周。

**这个项目花了你80个人月。利润率？10%。**

下一个项目——石化巡检。新的客户，新的SOP，新的环境，新的机器人型号。从头来过。

这就是今天工业机器人集成商的现实。ROS2解决了底层通信问题，但从SOP到执行的业务编排层，每个项目都在从零开始。找不到既懂ROS又懂视觉又懂行业规则的全栈工程师，找到了也留不住。

**问题不是机器人不够聪明。问题是没有人帮机器人理解人类的标准操作，并且正确地执行它们。**

## 什么是RobotClaw？

RobotClaw做三件事：

**理解**——读懂你的作业规程（SOP），将自然语言描述的操作步骤自动映射为机器人可执行的技能组合。

**执行**——在执行过程中持续判断和调整，确保每一步都正确完成。不是预设好固定路径然后盲目执行，而是在运行时根据实际环境做出智能决策。

**进化**——每一次执行都在学习。记录成功模式、失败教训、环境特征，让系统越用越正确、越用越高效。

**一句话：RobotClaw理解你的SOP，正确地执行每一步，并在每次执行中变得更好。**

RobotClaw不是又一个大模型，也不是又一个ROS中间件。它是连接人类标准操作和机器人物理执行之间的**操作系统级基础设施**——Physical AI Harness平台。

## 第一层：理解——读懂SOP，匹配能力

### SOP智能编译：让机器人读懂你的作业规程

传统方式：客户的作业规程（SOP）交给工程师，工程师写代码，测试，部署。改一条规则，重来一遍。

RobotClaw方式：SOP直接喂给编译器，大模型自动将自然语言拆解为结构化的Skill执行计划（DAG）。

**编译五步流水线：**

1. **步骤提取**——AI拆分SOP为结构化步骤（动作、目标、条件、参数）
2. **意图映射**——每步匹配Skill Registry中对应的Skill能力
3. **DAG构建**——自动处理条件分支、并行执行、循环遍历
4. **静态校验**——类型匹配、依赖完整性、前置条件可满足性自动检查
5. **人工审核**——可视化映射对照，一键确认或手动微调

**编译准确率目标：标准工业SOP ≥ 80%自动正确映射。**

这意味着：改SOP，不改代码。变更传播成本从"数周开发"降为"修改文档"。

### 场景应用模板：拿来就能用的行业方案

SOP编译器解决了"理解单条规程"的问题，但集成商面对的是整个场景——几十个巡检点位、多种检测方式、复杂的环境条件、不同的告警等级。

RobotClaw为常见工业场景预构建了**场景应用模板（Scene Templates）**：

| 场景 | 模板内容 |
|------|----------|
| **电力巡检** | 变电站巡检路线 + 红外热成像检测 + 表计读数识别 + 异常告警 + 报告生成 |
| **仓储物流** | 货架盘点 + 货物搬运 + 路径规划 + 库存核对 + 异常预警 |
| **矿山开采** | 矿道巡检 + 气体检测 + 结构安全评估 + 紧急撤离路径 |
| **管廊巡检** | 管道泄漏检测 + 温湿度监测 + 设备状态识别 + 定期报告 |

每个模板包含：预配置的SOP执行计划 + 已验证的Skill组合 + 环境参数模板 + 典型失败处理方案。

**集成商拿到模板后：**
- 80%的工作是**配置**——调整巡检路线、设备参数、告警阈值
- 15%的工作是**补充**——添加少量行业专属Skill
- 5%的工作是**定制**——处理客户特殊需求

**第一个场景80人月的时代结束了。用场景模板，首个项目10人月以内。**

### Skill生态：机器人的App Store

将机器人的每个能力标准化为**Skill**：导航、抓取、视觉检测、环境感知、数据采集、告警上报……

每个Skill有严格定义的接口：
- **输入/输出类型**——确保数据流在Skill之间无损传递
- **前置条件/后置条件**——声明式谓词，执行前自动校验物理世界状态
- **失败模式 + 恢复策略**——每种可预见的失败都有预定义的应对方案

Skill是RobotClaw的App Store。在电力巡检场景开发的导航Skill，物流仓储、矿山开采、农业作业项目可以直接复用。场景模板就是Skill的"精选组合包"。

**Teach Once, Embody Anywhere.** Skill不是"同一段代码到处跑"，而是同一个技能意图根据不同机器人本体重新具身化。在UR5e机械臂上训练好的抓取Skill，迁移到人形机器人或四足机器人时，系统会基于目标机器人的身体描述（关节范围、力矩限制、工作空间），自动进行约束适配和验证。

### 理解身体：e-URDF——机器人的"物理DNA"

要正确地控制一具身体，首先要理解这具身体。传统URDF只告诉系统"机器人长什么样"，但要正确执行任务，远远不够。

RobotClaw引入**e-URDF（扩展URDF）**，将机器人的物理描述从几何模型扩展为完整的**物理DNA**：不仅包含关节、连杆和传感器的几何信息，还描述每个关节的力矩限制和软限制、工具坐标系和工作空间边界、可执行的Skill清单、适用的仿真资产和Benchmark。

e-URDF让系统在行动之前，就完整理解自己要控制的这具身体——能做什么、不能做什么、边界在哪里。它是跨本体迁移（Teach Once, Embody Anywhere）的基础。

### 多模型协同：Provider统一能力接口

真实的物理任务不是一个大模型能独立完成的。一次机器人作业可能同时需要：VLM（视觉语言模型）看懂现场环境、VLA（视觉语言动作模型）生成动作候选、VLN（视觉语言导航模型）规划空间路径、世界模型预测动作后果、边缘小模型在端侧快速判断。

RobotClaw的**Provider**模块将这些异构模型统一封装为标准能力接口——可声明、可路由、可降级、可审计。不同场景可以灵活组合不同的模型能力，而不需要为每个模型写一套对接代码。

## 第二层：执行——运行时判断，正确完成

理解SOP只是第一步。在物理世界中，真正的挑战是**正确执行**。

物理环境千差万别。同一条"前往3号设备拍照"的指令，在不同温度、不同光照、不同障碍物环境下，执行细节完全不同。预设好一条固定路径然后盲目执行，一定会出错。

RobotClaw的执行引擎不是简单的"按计划走"，而是在执行过程中持续做出智能判断和调整：

- **环境感知**——实时获取传感器数据，理解当前环境与预期的差异
- **动态调整**——根据实际情况调整执行策略，不是死板地执行预设路径
- **异常处理**——检测到异常时，自主选择恢复策略：重试、换路、跳过、请求人工
- **状态追踪**——完整记录执行过程中的每一步决策和状态变化

**执行引擎核心能力：**

| 能力 | 说明 |
|------|------|
| **95%+ 自主率** | 绝大多数情况无需人工干预 |
| **可预测失败** | 每种失败有预定义的恢复策略：重试、重导航、跳过、熔断 |
| **完整诊断** | 失败时提供传感器快照、机器人位姿、错误链、前序Skill输出 |
| **级联熔断** | 连续3个Skill失败自动暂停，支持断点恢复 |
| **人工升级** | Dashboard实时告警，推荐操作建议，一键接管 |

> **核心承诺：不承诺100%成功，但保证100%可解释、100%可处理。**

### Dashboard——执行过程的驾驶舱

物理执行不能是黑箱。机器人在看什么、正在做什么、调用了哪个Skill、当前风险等级、执行进度如何——这些都应该被人类**实时看见**。

RobotClaw的Dashboard是执行过程的**驾驶舱**：机器人本体状态、技能图谱、任务进度、执行决策、人类接管入口，全部在同一个可观测界面中。

可观测性不是锦上添花，而是正确执行的一部分——只有人类能理解系统在做什么，才能审计、调试、复盘，并在必要时接管。

## 第三层：进化——越用越正确

RobotClaw不是一个静态的工具，而是一个**随使用持续进化的系统**。

### Practice——物理世界的"行车记录仪"

每一次任务执行，RobotClaw都在完整记录：传感器数据流、决策过程、Skill调用链、环境状态变化——全部按统一时间线对齐，形成一条完整的**执行实践记录（Practice）**。

这不是简单的日志。Practice是物理世界的"行车记录仪"——事故发生时可以逐帧回放，成功执行时可以提炼经验。每一条Practice都会被自动分析，提取出结构化的**记忆原子（Memory Atom）**：成功模式、失败教训、环境特征、最优参数。

### 三种记忆

- **任务记忆**：编译过的SOP执行计划直接缓存，同一SOP第二次编译耗时从3-5秒降为0秒
- **执行记忆**：从Practice中自动提取每个Skill在特定环境下的最优参数，从"默认配置"进化到"环境最优"
- **空间记忆**：构建时空记忆图谱——设备位置、环境基线、最优路径、历史异常区域，从"盲目探索"进化到"轻车熟路"

记忆不是静态存储，而是**活的经验库**。新的Practice不断注入，旧的记忆原子持续更新权重，系统对环境的理解越来越深。

### Know/How——让系统带着知识和经验执行

具身智能不是每次都从零推理。

**Know（离线知识炼化引擎）**：将论文、代码、项目文档、失败报告和Benchmark结果，整理成可检索、可复用的工程知识。不是普通知识库，而是把外部研究和内部实践**编译**成系统能直接使用的工程先验。

**How（在线经验注入引擎）**：当执行卡住、动作反复失败、风险升高时，How在关键时刻给出**最小、精准、带证据的提示**——降低步长、检查关节限位、回退到稳定技能、重新估计物体位姿。

Know负责"平时炼化知识"，How负责"现场及时提醒"。一个让系统更有学识，一个让系统更有经验。

### 自进化引擎：让Skill在评估压力下持续进化

记忆系统让机器人"越用越正确"，但RobotClaw更进一步——它让Skill本身在**评估压力**下持续进化。

**Auto/Darwin机制：** 当系统积累了足够的Practice数据，RobotClaw会自动生成候选Skill的改进版本。但改进不会直接上线——每一个候选Skill必须通过**六道关卡**才能晋升为正式Skill：

1. **多任务验证**——在多种任务中都优于现有版本
2. **扰动测试**——加入噪声、延迟、传感器误差，验证鲁棒性
3. **多初始状态**——从不同起始条件出发，验证泛化能力
4. **回归测试**——确保新版本不会让已有场景的表现变差
5. **安全验证**——通过全套安全检查
6. **性能基准**——执行效率不低于现有版本

只有全部通过，候选Skill才能替代现有版本成为**冠军Skill（Champion）**。这不是盲目迭代，而是**有评估压力的达尔文进化**——优胜劣汰，持续提升。

## 工程生态层：从单次任务到完整基础设施

### Swarm——从单机器人到多智能体协作

真实物理任务往往不是一个机器人单独完成的。巡检场景里，固定摄像头负责发现异常，机器狗负责抵近观察，机械臂负责操作阀门，人类专家在高风险节点确认。

RobotClaw的**Swarm**模块让具身智能从"单体执行器"走向"多智能体组织"——角色分配、任务分解、状态共享、空间避让、冲突消解、协同处置，都在统一框架下完成。

### Forge——新机器人接入变成"资产编译"

机器人生态最痛的地方，是每一个新本体都意味着新的SDK、新的协议、新的坐标系和大量胶水代码。

RobotClaw的**Forge**模块将机器人接入从"手写集成"变成**"资产编译"**：从机器人SDK、ROS2接口、文档和e-URDF出发，自动生成Skill清单、Provider清单、测试用例和生态元数据。接入一个新机器人，不再需要重写大量适配代码。

### ClawHub——让技能成为可流通的生态资产

如果每个项目都从零写技能，物理AI永远难以形成生态。RobotClaw的**ClawHub**让Skill不再只是代码片段，而是带有**版本、血缘、测试结果、适用本体和回滚机制**的技能资产。

一个Skill可以在Darwin中被评测、被提升为Champion Skill，也可以在出现问题时一键回滚到稳定版本。场景模板中的每一个Skill，都在ClawHub中有完整的生命周期管理。

## 为什么是现在？为什么是RobotClaw？

### 三股力量的交汇

**1. 大模型能力外溢**——大模型不再只理解文本和图像，它开始理解空间、动作、工具和身体。GPT-4、通义千问等大模型具备了理解自然语言SOP并映射到结构化执行计划的能力；多模态模型（VLM/VLA/VLN）让机器人能看懂环境、生成动作、规划路径。2年前做不到，现在可以。

**2. Physical AI浪潮**——NVIDIA、Tesla、Boston Dynamics等巨头全力推动机器人智能化。硬件成本下降，算力提升，世界模型和具身基础模型快速发展。2026年正在成为物理AI从概念走向工程的关键一年。

**3. 行业痛点积累**——工业机器人集成商在"80人月定制开发"的泥潭中挣扎了3-5年。每换一个客户、换一个场景，就要从头写代码。痛点从"隐约感觉"变成了"生死攸关"。

**RobotClaw站在这三股力量的交汇点上。**

### 技术壁垒

RobotClaw的壁垒不是大模型本身（大模型是通用基础设施），而是围绕大模型构建的**Physical AI Harness工程体系**：

- **场景模板**有复合壁垒——每个模板背后是行业Know-How + 验证过的Skill组合 + 环境参数经验，新进入者没有积累
- **Skill生态**有网络效应——Skill越多，平台价值越高，吸引更多开发者贡献Skill
- **记忆系统**有数据壁垒——使用越多，Practice积累越丰富，记忆原子越精准，新进入者无法复制历史经验
- **执行引擎**有工程壁垒——物理世界的失败模式需要在真实场景中逐个验证和覆盖
- **SOP编译器**有领域壁垒——各工业场景的SOP模式识别需要大量标注数据和领域知识
- **自进化引擎**有进化壁垒——Darwin评测压力下筛选出的Champion Skill，是真实场景千锤百炼的结果

## RobotClaw的愿景

我们相信，物理AI的落地不缺大脑，缺的是**让大脑正确驱动身体的操作系统**。

机器人需要理解人类的标准操作，在执行中持续判断和调整，并从每一次实践中学习进化。

**RobotClaw就是这个操作系统：**理解SOP（SOP Compiler + Scene Templates）、构建能力（Skill/e-URDF/Provider）、正确执行（执行引擎 + Dashboard）、持续进化（Practice/Memory/Know/How/Auto/Darwin）、协作扩展（Swarm/Forge/ClawHub）。

我们的目标：让每一个工业机器人集成商，都能用**配置模板**的方式交付项目，而不是用改代码的方式。让机器人越用越正确，让部署越来越快，让物理AI从实验室的demo走进每一座工厂、每一个仓库、每一片矿区、每一亩农田。
